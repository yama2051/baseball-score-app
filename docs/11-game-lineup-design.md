# 試合別ラインアップ設計書

## 1. 概要

新規試合では `GameForm` 内で自チーム側、出場選手、スタメン打順、守備位置、控えを設定し、試合登録と同時に確定する。試合登録後のラインアップは読み取り専用とする。登録時に設定されなかった既存試合に限り、PlayerList 下部から一度だけ登録できる。

## 2. コンポーネント構成

- `GameLineupEditor`: 選手選択、ホーム／アウェー選択、打順・区分・守備位置の共通入力 UI
- `GameLineupManager`: ラインアップ未登録の既存試合に対する一度限りの入力・確定
- `GameLineup`: 試合ID、チーム側、出場選手を保持し、スタメン・控えを分類して入力を検証
- `App`: 選手名簿と試合を管理し、新規登録時にラインアップを同じ試合データへ保存
- `GameResultList`: 確定したラインアップを読み取り専用で表示

## 3. ドメインデータ

```ts
type TeamSide = 'home' | 'away'
type LineupRole = 'starter' | 'reserve'

type LineupEntry = {
  playerId: number
  role: LineupRole
  battingOrder: number | null
  position: string
}
```

ラインアップは一試合につき一つを登録する。チーム側はその試合ごとにホームまたはアウェーから選択する。ラインアップは `GameResult` の一部として試合データと一緒に保存する。

## 4. ルールと検証

- 出場選手を1人以上選ぶ
- スタメンは必ず9人。各選手の打順は1〜9で、重複不可
- 控え選手には打順を設定しない
- スタメン・控えとも試合での守備位置を設定する。名簿のポジションを初期値として利用者が変更可能
- 同じ選手を重複登録しない

スタメンが9人未満または10人以上の場合は登録を拒否し、`FieldError` で現在人数と必要人数を通知する。控え選手は0人以上で登録できる。9人の選手名簿がない場合は、登録済み選手を追加してから試合またはラインアップを登録する必要がある。

## 5. ドメインモデル操作

- `withPlayer`: 控えとして選手を追加
- `withoutPlayer`: 選手をラインアップから外す
- `updatePlayer`: 出場区分、打順、守備位置を更新
- `starters`: 打順順のスタメン一覧
- `reserves`: 控え一覧
- `validate`: 登録可能な内容か検証し、問題があればメッセージを返す
- スタメンがちょうど9人か検証し、不足・超過時は必要人数と現在人数を返す

`GameLineup` は入力値を直接変更せず、新しいモデルを返す操作で状態を更新する。

## 6. 保存と表示

- 新しい試合のラインアップは試合登録時に他の試合情報と同時に保存する
- 登録後の試合カードはスタメン・控えを表示するが編集操作を提供しない
- 既存試合にラインアップがない場合だけ一度限りの登録フォームを提供する
- 既存試合への登録後は `GameResult` にラインアップが保存され、再編集フォームの対象外となる
- 選手名簿から削除された選手は、編集中の候補と表示名から除外する
- 新規試合と既存試合のラインアップ登録時に、スタメン9人を必須にする
- 入力エラーは共通の `FieldError` コンポーネントで表示する

## 7. データフロー

```text
players ──┐
          ├─> GameForm ─> GameLineupEditor ─> GameLineup
games ────┘                    │                    │
                               └─> App ─> localStorage

既存試合（ラインアップなし） ─> GameLineupManager ─> 一度限り確定
```
